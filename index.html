01The pitch

You're running a swarm of AI agents that write code, run tests, and ship commits around the clock. You should be able to lean back, slide open a keyboard, and thumb tmux attach to see what they're up to — from a phone older than the concept of an AI coding agent. RETROTERM 2 is that. It shouldn't work. It does.

🤖 Attach to the swarm

SSH straight into the tmux where your Claude Code agents live. Read their output, answer a prompt, nudge a stuck one — a control surface for the fleet, in your palm.

⌨︎ Tactile input

A five-row physical QWERTY that clicks. Your thumbs already know it. No autocorrect will ever turn rm into Rm.

🔒 Key-only access

Passwordless public-key SSH. The key lives on the device; the server never sees a password. Getting there required minor surgery — see below.

📡 Local, cloudless

Joins your Wi-Fi, reaches your box, attaches your session. No account, no cloud relay, no telemetry a 2010 build could phone home even if it wanted to.

04What this actually is

It's a 2010 Motorola Droid 2 running Android 2.2, turned into a passwordless SSH terminal into a homelab. It is not a product, it is not for sale, and nothing was manufactured. The “launch” is the joke. The engineering under it is real, and it was more involved than it had any right to be — a phone this old can't complete a modern SSH handshake, and the SSH app that runs on it ships a signature bug. Both had to be fixed. That's the part worth reading.

05How it was actually done

Four real problems, four fixes. None of them were “install an app.”

  1. A door the phone can knock on. A 2011-era SSH client only speaks SHA-1-era key exchange, which modern OpenSSH refuses outright — the handshake dies before login. Fix: a second SSH daemon on a side port that additionally accepts the legacy algorithms, RSA host key only. The main port stays fully modern. 
    # /etc/ssh/sshd_config_legacy — side port for vintage clients
Port 2222
HostKey /etc/ssh/ssh_host_rsa_key
KexAlgorithms +diffie-hellman-group14-sha1,diffie-hellman-group-exchange-sha1
HostKeyAlgorithms +ssh-rsa
PubkeyAcceptedAlgorithms +ssh-rsa
Ciphers +aes128-ctr,aes128-cbc
  2. A client that signs correctly. The original ConnectBot on this build produced RSA signatures the server rejected as “invalid format” — key auth could never succeed. Fix: VX ConnectBot, the fork maintained for old Android, whose signer is repaired.
  3. Getting the key onto it. No cloud sync, no working file picker path. But the phone is rooted, so the key went straight into the app's database — the private key encoded as PKCS#8, the public key as X.509, written into ConnectBot's SQLite pubkeys table, with a matching host row linked to it. The public half was authorized on the server. Gotcha that cost an hour: a hand-injected host row leaves columns the UI normally fills as NULL — and the client calls .equals() on one of them (useauthagent), so it authenticates perfectly and then crashes with a NullPointerException before requesting the shell. Fill the nullable columns.
  4. Doing it all remotely, and proving it. The whole setup was driven over a USB cable with no eyes on the phone: read the app's schema, inject the key, then capture the raw framebuffer (/dev/graphics/fb0) to see the screen and inject input events to drive the UI — connect, watch, confirm. Verified server-side by the one line that matters: a real login shell on a pty, authenticated by key, no password. Second gotcha: the app caches its database in memory, so it must be fully killed — not just backgrounded — before it will re-read an edited database.

Result: open the saved host, and you're at a shell. tmux attach, and a phone from 2010 is sharing the exact session as everything modern on the network.
